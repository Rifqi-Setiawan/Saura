# Resolved implementation decisions

Approved build scope: local end-to-end prototype from supplied documents, no public deployment or credentials. Delivery tier remains default demo (the product's MVP label does not override governance tier). Independent QA review explicitly required by this contract.

1. Immutable provenance is docs/source/*.md. Source 0 and 7 and UT-12 override obsolete totals: fixture Oct 24–30 totals 180 actual, 224 expected, 44 lost kWh, Rp66,000. This is a custom demonstration range, NOT a calendar week. Calendar weekly reports are Monday–Sunday. Keep full precision for computation and round at explicit display/monetary boundaries; fixed demo expected 32.0 uses an explicitly labeled simulation fixture, not a hidden change to the physical formula.
2. Recovery counts consecutive VALID reports after intervention. Missing days pause the count. Any valid ratio below .90 resets progress; ACTION/CRITICAL additionally reopens a ticket. .85–.89 NORMAL readings do not resolve or reopen; require three new qualifying reports. Editing an earlier report recomputes assessment/history and recovery without duplicate notifications.
3. No report before local 20:00 is pending, not NORMAL or NO_DATA. After cutoff NO_DATA has null actual/performance/gap/money. Missing/zero/invalid irradiance produces unavailable assessment, no division by zero, no fault/ticket invented. Suspicious >1.3 expected requires reconfirmation with no operational status. Model these as quality/pending state separately from four operational status enums. No negative/nonfinite numbers.
4. Historical streaks require consecutive local calendar days with valid assessments; missing/invalid data breaks status streaks. Cloudy guard caps severity at ACTION and forbids auto-ticket. Critical automatic ticket is idempotent per active incident; no visit authorized before manager approves a concrete estimate, assigned technician and schedule. Cost changes invalidate prior approval and generate immutable audit events. Do not regress terminal tickets with arbitrary updates.
5. Bind manager/operator/site via explicit admin assignment or single-use invite; never let arbitrary bot user claim a real location. Sim demo has isolated configured identities; no reusable default production password. Manager sees only owned sites; technician only assigned tickets and necessary location evidence; admin role does not silently imply manager approval. All endpoints and tool calls enforce scope in code. Webhook secret and update deduplication, report confirmation and callback ownership mandatory. Login must be rate-limited with secure session/token handling; no secrets in browser storage or logs.
6. FSM covers hybrid vs off-grid choice, battery question, active site selection and callback expiry. CSV explicitly includes target site, size/row limits, locale-aware values and duplicate policy; every replacement is audited. Tools cannot bypass human OCR confirmation, identities, role rules or cost approvals.
7. Guardrails distinguish prohibitions ('jangan naik atap') from instructions. Free-form LLM repair instructions are never actionable. Physical cleaning advice disabled until human energy expert approves playbook; ground/unknown mounting is not authorization. Permit observation from safe ground only, never switching/touching electrical equipment. Photo/LLM content is untrusted.
8. One simulation clock governs demo dashboard date, cutoff, reminders, technician intervention and recovery. Reset is transactional and scoped to simulated data only; never deletes real sites/users. Advance reproduces the approved demo technician step as an explicit audited SIMULATION event, not a real technician impersonation. Seed starts with the documented demo incident once, report/ticket actions cannot duplicate it. No future reports before advance; no real Telegram sends from simulation without separate approval.
9. Weather boundaries use per-site timezone, source/as-of timestamps, bounded requests/cache, Open-Meteo then NASA daily then climatology. If all fail show unavailable. Forecast daily total at 16:00 is provisional vs still accumulating E-Today: label as provisional and avoid claiming calibrated fault certainty; preserve report observation time. PR calibration cannot silently normalize a known incident or simulation; only eligible valid readings, explicit provenance and manual recalibration.
10. Runtime Python 3.12 available; implement compatible Python >=3.11. Use stable supported dependency versions after compatibility inspection, lock them and document differences from old Next.js14 recommendation. Docker compose may be supplied for portability but MUST NOT be executed. Local isolated SQLite acceptable; SQLAlchemy migrations must also be PostgreSQL-compatible, actual PG integration remains unverified until exercised in an approved isolated instance. No connection to existing shared PostgreSQL.
11. Protected acceptance API: backend/app/engine/acceptance.py exposes assess(actual_kwh, expected_kwh, irradiance, previous_ratios=()) -> dict status/performance/gap_kwh/loss_idr/reason_code, tariff default 1500; expected_energy(kwp,irradiance,pr=.79) -> float; weekly_totals(actual,expected,tariff=1500) -> dict actual_kwh/expected_kwh/gap_kwh/loss_idr; recovery_status(ratios) -> RESOLVED/REOPENED/MONITORING. These thin public facades must delegate real domain rules, never duplicate test-only logic. Status on suspicious/unavailable is null.
12. Verification must cover protected tests plus all UT/BT cases, auth isolation, ticket FSM/cost change, weather fallback failures, simulation determinism and actual HTTP/browser primary journey. Live OCR 30-image accuracy, live Telegram latency, real datasets, expert review and event user studies remain separate unavailable evidence until actually run. Never present mocks/generated inverter photos as real field validation.
